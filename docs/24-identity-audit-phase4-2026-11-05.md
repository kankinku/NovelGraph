# [04/12] 인물 동일성 후보 충돌 검사 — 2026-11-05

> **판정: 저장 전·승인 전 인물 ID 충돌 검사 추가 및 실제 후보 제한적 검증. 전체 인물 동일성 정확도는 미측정이며 [04] 실사용 게이트는 아직 미달.**

## 1. 확인한 기존 동작과 최소 변경 이유

현행 NovelGraph는 **하나의 객체가 누구인지는 안정된 `entity_id`로 결정**하고, `name`을 자동 동일 인물 병합 키로 사용하지 않는다.

- `graphify_bridge.py`: 같은 ID·다른 이름/유형은 그래프 투영 중 충돌로 거부하며, 같은 이름·다른 ID를 임의 병합하지 않는다.
- 승인된 `relation` 후보는 `relation_type: same_person_as` 같은 별도 관계를 근거와 함께 나타낼 수 있다. **관계가 존재해도 두 ID가 자동으로 하나로 합쳐지는 것은 아니다.**
- `world_state.py`: 이미 적용된 현금 거래와 같은 `transaction_id`로 추가 현금 변경을 시도하면 `event_key` 충돌로 거부한다. **서로 다른 거래 ID에 같은 과거 지급을 잘못 적는 것은 아직 자동 검출 대상이 아니다.**

이미 안전한 규칙을 전면 수정할 필요는 없다고 판단했다. 부족한 기능은 **후보가 승인되기 전에 동일 인물 여부를 사람에게 확인하도록 이름·ID 충돌을 보여주는 기능**이었으므로 작은 읽기 전용 명령만 추가한다.

## 2. 신규 `identity-audit` CLI

```bash
ROOT=/shared/NovelGraph-data/works/ashcroft-pilot-20261104

cd /shared/NovelGraph
.venv/bin/python -m novelgraph --data-root "$ROOT" \
  identity-audit --work-id ashcroft_pilot --episode 5
```

**검사 범위:** 선택한 작품·회차까지 등록된 `proposed` 및 `approved` 상태의 `entity` 후보. `rejected`는 제외.

| 판정 코드 | 모델/검수자가 확인할 문제 |
| --- | --- |
| `same_name_distinct_ids` | 같은 종류의 두 인물이 **동일한 표기명**으로 서로 다른 ID에 기록됨. 동명이인일 수도 있으므로 자동 병합 금지 |
| `same_id_multiple_names` | 하나의 ID에 여러 표기명이 연결됨. 정식 이름·별명·직함일 수도 있고 잘못 병합된 별개 인물일 수도 있음 |
| `same_id_incompatible_types` | 하나의 ID를 인물과 조직 등 서로 다른 객체 유형으로 재사용함 |

- 반환 정보: 문제 유형, 해당 ID, 근거 후보 ID, 회차, 원본 SHA-256, 문자 오프셋, 후보 승인 상태.
- **원문 문장·표기명 자체는 CLI 출력에 포함하지 않는다.**
- 데이터베이스를 **SQLite 읽기 전용 연결(`mode=ro`)**로 열며, 자동 인물 병합·동일성 확정·공식 상태 적용을 하지 않는다.
- 저장 후보의 불변 SHA 기반 `candidate_id`를 재계산해 변조된 저장 후보는 거부한다.
- `needs_human_review`는 충돌을 발견했다는 뜻이고, `semantic_identity_verified: false`는 충돌이 없어도 유지한다.
- 현재 검사는 **문자열이 정확하게 일치하는 이름만 감지**한다. 음차·호칭 변화·철자 변화·문맥 속 지칭의 의미 유사성은 분석하지 않는다.

## 3. 테스트 규칙

합성 한국어 소설 사례를 사용하여 다음을 검증한다.

- 서로 다른 ID에 같은 인명 → 충돌 보고, **자동 병합 0**.
- 동일 ID에 여러 호칭·정식명 → 충돌 보고, 자동 동일인 인증 없음.
- 한 ID·같은 이름의 여러 화 재등장 → 중복 오류로 오인하지 않음.
- 동일한 글자 표기의 인명과 회사명 → 유형이 다른 만큼 이름만으로 병합하지 않음.
- 동일 ID에 인물/조직 타입 중복 → 검토 대상으로 보고.
- 거절된 후보는 추출 집합에서 제외.
- 작품·회차별 범위 격리.
- 저장된 후보의 JSON 변조 → 해시 오류로 거부.
- 입력 유형 오류 → 비정상 중단 대신 명확한 검증 오류.
- DB 없는 환경에서는 새 DB를 자동 생성하지 않음.
- Graphify에서 같은 표기명을 지닌 두 노드를 구분하고, 승인된 명시적 `same_person_as` 관계만 근거를 가지고 연결하는지 검증.
- 기존 세계 상태의 동일 `transaction_id` 중복 지급 거부 테스트를 유지한다.

## 4. 실제 비공개 데이터 검증 범위

동일 작품 1~5화의 **이미 등록된 인물 후보 5건**에서 명시적 이름·ID 충돌은 **0건**이었다. 이 결과는 등록된 다섯 후보만 검사한 것으로, 작중 모든 인물을 누락 없이 추출했거나 별칭 관계까지 해결했다는 의미가 아니다.

- 기존 공식 DB: `proposed` 26건, 적용 완료 상태 사건 0건 유지.
- 실제 DB 파일 SHA-256: `identity-audit` 실행 전후 동일.
- 실제 원고 및 모델 예비 검토 결과는 공개 GitHub에 업로드하지 않았다.
- 인간 독립 금표준 정답표 부재: 인물 동일성 정밀도·재현율 **미측정**.

## 6. 남은 개발 과제

1. 원고의 모든 인물과 별명·호칭·직책에 관한 독립 정답표가 확보되면 현재 ID별 관계와 비교한다.
2. 동일인이라고 승인한 별칭 증거를 기존 `relation` 스키마로 표현하고 Graphify 추적을 검증한다. 필요가 확인되지 않은 **노드 자동 병합은 하지 않는다**.
3. **동일 거래 ID를 재사용했을 때만** 중복 지급이 차단되는 현재 범위를 유지한다. 서로 다른 거래 ID가 실은 같은 과거 지급 사건인지는 독립 근거와 사람 검토가 필요하다.
4. 본문 1~5화의 등록 후보가 적으므로 전체 원고 인물 분석 성능을 아직 합격 처리하지 않는다.
