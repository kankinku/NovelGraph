# NovelGraph 현재 상태 중심 재설계 — 2026-11-09

## 목적과 경계
집필 LLM이 요청하는 작품의 **정확한 현재 상태**를 제공한다. 작문 엔진이 아닌 작품 DB. Grill-me 확정 27문항이 요구사항의 기준이다.

## 선택한 접근과 대안
1. 완전 재개발: 기존 승인·이력·그래프 기능을 잃을 위험이 큼.
2. **채택: 기존 SQLite 증거/승인/불변 이벤트 재생 + Graphify 파생 그래프를 재사용하고 범용 현재 상태와 정확 범위 조회를 추가.**
3. 자유 JSON 키값: 정보 충돌과 시간/수치 오류를 막을 수 없어 제외.

## 확정 원칙
- 확정 원고만 공식 원장에 반영, 초고는 임시 후보/검사. LLM(Moon/SDK)이 JSON 후보를 추출한다. 외부 유료 LLM/API는 새로 추가하지 않는다.
- 상태는 최신 회차에 따라 갱신하고, 사건 이력과 과거 원문 근거·회차·문자 범위를 보존한다. 현재 상태와 과거 이력 조회를 분리한다.
- 중심 노드 + 가지 + 교차 연결. ID와 별칭으로 동일 개체 관리. 자산(유동/주식/채권/부동산)과 부채는 분리하고 단위 일치시에만 합계 계산.
- 객관적 사실 ≠ 대사 속 주장/소문/추측. 미래 예정 ≠ 현재 완료. 알지 못하는 값은 미확정. 인물 지식의 미언급 ≠ 모른다는 확정.
- 시간은 현재 시점 중심이며 증거상 확실할 때만 갱신한다. 사건은 발생 시각과 원문 회차를 분리한다.
- 요청한 노드 범위만 제공한다. "내역" 요청이 없으면 이력은 반환하지 않는다. 현재값·마지막 변경 회차·작중 시간·원문 근거·확정 여부를 포함한다.
- 충돌 시 원고 반려, 요청한 AI 1차 판단, 사용자 2차 결정. 원고 수정은 예방하지만 DB 추출 오류 파급 시 예외적 수정/재검증.
- 역사 고증은 외부 자료 별도 검증. Graphify는 원장 쓰기 권한 없음.

## 단계별 범위
A. 유형이 제한된 상태 갱신/증거 이력. B. 질의 범위별 현재값/선택적 내역. C. Graphify 현재 노드 투영.
D. 집필 AI의 후보 추출/검증/충돌 반려 계약 정리. E. 전체 테스트 및 독립 리뷰.
자동 승인, 별칭 자동 결합, 복잡한 과거 원고 수정/역사검색 연동, 실원고 실증은 별도 위험 검증 후 단계적으로 도입한다.
