# NovelGraph Production-Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 NovelGraph MVP를 실제 한국어 웹소설의 설정·상태·연속성 검수에 반복 사용 가능한 도구로 고도화한다.

**Architecture:** ChatGPT가 원문 의미 후보를 만들고 기존 Moon MCP가 Python CLI를 실행한다. SQLite가 승인·상태·근거 이력의 기준 원장이고 Graphify는 조회용 파생 그래프다. 실제 원고·후보·DB는 공개 Git 저장소 밖에 둔다.

**Tech Stack:** Python 3.12, 표준 `unittest`/SQLite/`Decimal`, 설치된 `graphifyy==0.9.102`, Moon MCP 및 GitHub.

**Spec:** [기존 개발 계획](../../07-implementation-plan-2026-11-04.md), [실제 1~5화 파일럿](../../17-real-private-corpus-pilot-2026-11-04.md), 본 대화에서 합의한 MVP→실사용 12단계 계획.

## Global Constraints

- 원고 자동 집필·자동 퇴고 제외. LLM 의미 추출은 ChatGPT가 담당하며 외부 유료 LLM API 필수화 금지.
- 사용자 원고·평가 정답표·후보·DB·모델 출력의 원문을 **public GitHub에 업로드하지 않음**. 작업 데이터는 `/shared/NovelGraph-data`에만 보관.
- 이미 실행 중인 Moon MCP 서비스 및 예약 포트 2999/3000은 변경하지 않음.
- 구형 Moon 원본 `909e00d`는 미복구. 이전 테스트 690개 완료 주장과 현행 테스트를 혼동하지 않음.
- 전체 데이터 파괴·기존 원고 덮어쓰기·`git reset --hard` 금지. 테스트는 private 원본과 분리된 worktree 및 임시 DB를 사용.
- 새 기능은 **실패 재현 테스트 → 최소 코드 변경 → 관련/전체 테스트 → Diff 감사 → PR** 순서.
- 사용자의 승인과 모델의 후보 판단은 별개. 현재 `--reviewer` 식별 문자열은 **인증이 아님**.
- 원고의 미래 회차에서 공개된 사실이 과거 회차 시점의 '당시 알려진 상태'에 무단 포함되면 안 됨.
- 정밀도·재현율·F1은 독립 검수 정답표가 있는 경우에만 출력. 빈 정답표를 품질 100%로 해석하지 않음.

## Review Focus — 가장 위험한 다섯 가지

1. **반복 거래:** 3·4·5화에서 한 번의 과거 지급 총액이 반복 언급되더라도 현금에서 여러 번 빠지면 안 됨. [Task 04, 06]
2. **승인 위조:** 모델 검토나 `reviewer` 문자열만으로 사용자 확정 승인이라고 기록하지 않음. [Task 05]
3. **미확정 계획:** 계약 의사·회수 계획·지원 중단 결정은 실제 현금·권리 변동으로 처리하지 않음. [Task 03, 06]
4. **이전 판본:** 원고 수정으로 SHA가 달라지면 변경된 구절의 옛 근거를 자동 재사용하지 않음. [Task 07]
5. **시점 오염/데이터 혼합:** 뒤늦게 공개된 사건과 서로 다른 작품의 원고·상태·정답표를 혼합하지 않음. [Task 07, 10, 12]

## Checkpoint and Reporting Contract

각 Task는 이 순서로 기록한다: **현재 증거 → 실패 테스트 → 최소 수정 → 관련 테스트 → 전체 회귀 테스트 → 독립 리뷰 또는 자체 리뷰 명시 → Git diff → PR → Moon 재검증**.

실제 원고는 표본이자 비공개 데이터이며, 그 일부를 테스트 픽스처나 공개 문서에 복사하지 않는다. 인간 정답표가 없는 Task 02는 정답표 **준비**까지만 진행하고, 인간 검증이 완료된 것처럼 기록하지 않는다.
