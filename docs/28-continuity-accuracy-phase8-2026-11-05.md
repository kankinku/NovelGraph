# [08/12] 연속성 검출기 판정 정밀화 — 2026-11-05

> **상태:** 실제 검출기에서 재현한 버그 2종을 최소 수정. 독립 인간 정답표가 없어 실제 원고의 precision/recall/F1은 **미측정**이다.

## 1. 기존 기능과 범위

`check-continuity`는 현재 공개 원고가 아니라 **사용자가 승인했다고 기록된 후보** 및 근거를 대상으로 동작한다. 정상적인 원고의 전반적 정확성을 자동 확인하는 도구가 아니다.

기존 분류의 의미는 다음과 같다.

| 판정 | 기준 |
| --- | --- |
| `CONFIRMED_CONFLICT` | 같은 사건의 같은 시점에 날짜·요일 또는 명시적 같은 장면의 모순이 있고, 불확실성이 없으며 승인 근거가 두 건 모두 있는 경우. 승인된 계약 상태 원장과 사실 진술이 동일한 알려진 시점에서 충돌할 때도 사용 |
| `NEEDS_REVIEW` | 시점·장면 변화, 행동 반복, 금액·위치 차이가 있으나 동일 조건의 모순임을 단정할 만큼 근거가 없을 때 |
| `EXPLAINED_CHANGE` | 이동·수정 합의·재개 등 **확정된** 변경 증거가 이전 값과 이후 값을 직접 연결할 때 |
| `INSUFFICIENT_EVIDENCE` | 한쪽 진술의 `certainty=uncertain`, 연결할 수 없는 변경 사건, 근거 부족 등으로 확정할 수 없을 때 |

분류는 `source_sha256`과 각 회차의 Unicode 인용 위치·후보 ID를 반환한다. 인용문 자체는 출력하지 않는다.

## 2. 재현·수정한 문제

### 문제 A — 불확실한 변경을 정상 변경으로 오판

기존 `_matching_change`는 `certainty=uncertain`인 변경도 `EXPLAINED_CHANGE`의 증거로 받아들였다. ‘계약액이 바뀌었을지도 모른다’는 모델의 예비 추정만으로 15만 달러→30만 달러의 차이를 합리화할 수 있었다. 완료 행동의 반복도 같은 문제가 있었다.

**수정:** `certainty=confirmed`인 변경 후보만 두 값 또는 완료 행동을 잇는 설명으로 인정한다. 불확실한 변경은 독립적으로 `INSUFFICIENT_EVIDENCE`로 기록하며, 두 확정 사실 사이의 차이는 계속 `NEEDS_REVIEW`로 보존한다.

### 문제 B — 뒤늦게 알려진 과거 계약의 원장 대조 누락

기존 계약 연속성 검사는 `effective_episode`(사건 발생 시점)만 넣어 세계 상태를 재생하면서, `source_episode`(정보 공개 시점)까지 같은 과거 회차로 제한했다. 예컨대 **1화에서 서명된 계약이 3화에서 처음 밝혀진 경우**, 4화에서 ‘1화에는 서명되지 않았다’라는 주장이 나와도 서명 사건의 원장을 찾지 못했다.

**수정:** 기존 `_replay`에 선택적 `known_at_episode` 인자를 추가해 **실제 발생 시점의 상태를, 해당 주장이 나오던 회차까지 알려진 정보로 재생**한다. 일반 `world-state`의 회차별 조회 동작은 변경하지 않는다. 계약 증거 조회도 같은 두 가지 시점을 이용한다.

- 2화 당시에 아직 알려지지 않은 3화 공개 사실은 **2화 진술을 소급해서 오류로 단정하는 데 사용하지 않는다.**
- 4화 진술에는 3화까지 공개된 1화 서명 사실을 사용할 수 있으며, 충돌한다면 원장 사건과 주장 양쪽의 원문 근거를 연결한다.

## 3. 합성 테스트와 비공개 파일럿

새 합성 테스트 5개:

1. 불확실한 금액 변경이 확정적 정상 변경으로 처리되지 않음
2. 불확실한 재시도 설명으로 완료된 행동의 반복을 합리화하지 않음
3. 늦게 알려진 과거 계약을 이후 회차의 계약 상태 주장과 비교하여 충돌을 탐지
4. 이후 공개된 사실이 공개 전 회차의 주장에 소급 적용되지 않음
5. 동일 순간·동일 맥락의 확정 금액 모순은 양쪽 근거를 포함하는 충돌 판정 유지

실패 재현 결과 **5개 중 3개 RED, 이미 정상인 2개 GREEN**. 수정 후 **5개 GREEN**으로 확인. 기존 날짜·요일, 장면·이동, 금액, 완료 행동, 계약·지분 이전, 승인 로그 등의 회귀 테스트를 유지한다.

실제 비공개 파일럿 1~5화의 공식 DB는 후보 **26건 전부 `proposed`**이고 공식 승인된 `continuity_fact` 0건이다. `check-continuity --episode 5`는 `reviewed_facts=0`, 검출 0을 반환한다. **이는 평가할 승인된 사실이 없다는 뜻이지 실제 소설의 모순이 0이라는 의미가 아니다.** 실제 DB는 읽기 전용 확인만 했으며 바이트 SHA는 변하지 않았다.

## 4. 범위·제한 및 후속 작업

- 기존 `source_episode`·`effective_episode` API를 유지하며 전체 세계 상태 알고리즘을 변경하지 않는다.
- 인물 별칭 추론, 장면 ID 추출, 계약 당사자 추정, 누락 사실 자동 발견, 날짜·요일 의미 추론은 여전히 ChatGPT/검수 과정의 책임이다.
- 실제 독립 정답표가 없으므로 사건별 **precision/recall/F1은 계산하지 않는다.** 합성 테스트 통과율을 추출 정확도로 표시하지 않는다.
- 검출 범위 밖에서 발생한 원고 오류와 작성자가 의도한 정상 변화의 구분은 별도의 독립 검수 결과로 확인해야 한다.
