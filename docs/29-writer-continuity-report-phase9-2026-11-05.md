# [09/12] 작가용 연속성 검토 Markdown 보고 — 2026-11-05

> **범위:** 기존 `check-continuity`의 승인 후보 비교 결과를 **읽기 전용으로** 작가가 검토할 수 있도록 변환한다. 원고 자동 수정, 미승인 후보 판단, 새로운 LLM API 및 DB 스키마 변경은 없다.

## 1. 왜 필요한가

기존 JSON은 기술적으로 `finding_id`, `category`, `reason_code`, `evidence`를 제공하지만, 작가가 어느 회차·어느 문자를 확인해야 하고 무슨 종류의 검토가 필요한지 직접 편집해야 한다. 본 단계는 기존 판정을 **확대하거나 정확도 개선을 주장하지 않고** 짧은 작업 보고서로 정리한다.

## 2. 사용법

```bash
cd /shared/NovelGraph
.venv/bin/python -m novelgraph \
  --data-root /shared/NovelGraph-data/works/ashcroft-pilot-20261104 \
  continuity-report --work-id ashcroft_pilot --episode 5
```

표준 출력은 Markdown 문서다. 원문과 DB를 변경하지 않고, 저장이 필요하다면 **비공개 데이터 경로로만** 셸 리다이렉션한다. 기존 `check-continuity`의 JSON 출력은 변함없다.

요약은 확정 충돌 / 추가 검토 / 근거 부족 / 설명된 변화로 구분하고, 각 항목에 대상 ID, 필드, 비교값, 검출 이유 코드, 권고 검토 사항, 증거의 등록 회차·사건 발생 회차·Unicode `[start,end)`·후보 전체 ID·등록 SHA-256을 적는다. 원문 인용은 출력하지 않는다.

## 3. 안전과 판정의 한계

- 보고서는 `check_continuity`를 그대로 호출해 승인 로그 검증과 시점 처리를 재사용하며, SQLite `mode=ro`로 연다.
- DB가 없거나 해당 회차가 등록되지 않았거나 승인 로그가 없는 위조 후보가 있으면 실패 처리한다.
- 근거가 비어 있거나 회차·위치·SHA/후보 식별자가 잘못된 탐지 항목은 **보고서 출력 전에 거부**한다.
- 같은 `finding_id`의 완전 동일 결과만 1건으로 표시한다. 같은 ID인데 다른 내용을 담은 결과는 조용히 병합하지 않고 오류를 낸다.
- `CONFIRMED_CONFLICT`는 **승인된 구조화 사실 간의 충돌**이며 소설의 최종 오류 판정이 아니다. 정상적인 변화나 모호한 정보는 검토 필요/근거 부족/설명된 변화로 분리한다.
- 현재 원고가 DB에 등록된 원고 판본과 같다는 것을 이 보고서가 별도로 검사하지 않는다. 운영 시 `source-version-audit`를 사용한다.
- 독립 인간 검토에 따른 정밀도·재현율·F1은 여전히 미측정이다. `reviewer` 텍스트는 신원 확인이 아니다.

## 4. 테스트 및 비공개 점검

합성 테스트 `tests/test_continuity_report.py`에서 보고서 명령 미구현 **9개 RED** 확인 후, 구현 뒤 **9/9 GREEN**을 확인했다.

Moon 전체 회귀 테스트 `/shared/NovelGraph/.venv/bin/python -m unittest discover -s tests -v`: **156/156 통과 (377.942초)**. 테스트 명령과 실행 기록은 비공개 경로 `/shared/NovelGraph-data/research/production-phase9-full-suite.log`에 남겼다.

검사 범위: 금액 확정 충돌의 양쪽 근거 위치, 위치 변화의 추가 검토 분류, 변경을 뒷받침하는 설명된 변화, 연결되지 않은 변경 근거 부족, 미승인 사실 0건의 무오류 오독 방지, 위조 승인 거절, DB 바이트 SHA-256 불변, 미등록 회차와 DB 부재의 안전한 실패, 근거가 없는 항목 거절·중복 식별자 처리.

비공개 `ashcroft_pilot`의 공식 DB를 읽기 전용으로 5화까지 점검한 결과 승인된 연속성 사실은 **0건**이다. 따라서 표시되는 검출 0건은 소설이 무오류라는 뜻이 아니며, 실제 오류 사례의 편집 편의성 평가에도 쓸 수 없다. 읽기 전후 공식 DB SHA-256은 동일했다. **실제 승인 사례를 대상으로 한 작가 검토는 미완료**다.

### 잔여 작업

독립적으로 검토된 원고 사례의 승인·근거가 확보되면 작가가 보고서로 실제 수정을 결정할 수 있는지 평가하고, 필요한 표현만 점진적으로 보완한다. 모델 평가를 공식 승인으로 승격하지 않는다. 후속 [10/12] Moon 작업 절차 정리에서도 이 명령과 판본 감사를 순서에 포함할 예정이다.
